# 規格との対応

このツールが書き出す VCA ファイルが、DCS v3.14 のどの決まりに関わり、どう守っているかの一覧です。このツールは VCA を読まないので、受ける側(相手が決まりを破ったデータの扱い)はありません。

- 「番号」は [vca-guide](https://github.com/NrivYuki/vca-guide) の [docs/requirements.md](https://github.com/NrivYuki/vca-guide/blob/main/docs/requirements.md) の番号です(R 義務・S 推奨・O ほかの言い方の義務)。番号の無い決まり(データ型の定義など)は節の番号で書きます。
- 「扱い」は、テスト(`tests/conformance.test.js` で確かめる)・対象外(このツールに当てはまらない)・利用者(書き出したファイルを使う人が守る)のどれかです。テスト以外は理由を書きます。
- 「送る側」は書き出しで守ること、「受ける側」は読み込みでの扱いです。- はその側が無いことを示します。
- どのテストが確かめているかは [conformance-tests.md](conformance-tests.md) にあります(`tools/trace.js` が作る)。`tools/trace.js --check` は、次のどれかがあれば失敗します。
  - テストの無い「テスト」の行
  - 正常系(正常・規格の例)と異常系(異常・境界)のどちらかが欠けた行([異常系を求めない行](#異常系を求めない行)を除く)
  - 表に無い番号を指すテスト、理由の無い行

## 異常系を求めない行

書き出す形が入力によらず決まっている行です。規格に反するデータを作る入力が無いので、異常系(誤った入力を誤りにする・境界の値)のテストを作れません。正常系は、点数(360・1440)・写した眼(右・左)・穴の有無を変えて確かめます。

| 番号 | 異常系を求めない理由 |
|---|---|
| R182 | REQ はいつも `REQ=FIL` で、入力で変わらない |
| 7.5.6 | 形式はいつも 1 で、入力で変わらない |
| R003 | 左右のレコードはいつも同じ値を 2 つ書く(数の入力の誤りは画面が先に止め、`tests/ui/` で確かめる) |
| R234 | TRCFMT の欄はいつも 5 つで、入力で変わらない(眼の誤りは R037 の行で確かめる) |
| R038 | TRCFMT はいつも右眼・左眼の 2 つ |
| R024 | R の行はいつも TRCFMT の直後で、値の数は点数そのもの |
| R207 | 点数と半径は整数にしてから書く |
| S013 | `ZFMT=0` はいつも R の後に書く |
| R027 | 同上 |
| R036 | 半径を測る向きは計算で決まり、入力で変わらない |
| R032 | 寸法は書いた半径から計算する |
| R072 | 穴が無いときはいつも `DRILLE=0` を 1 行 |
| R055 | 基準はいつも `C` |
| R056 | 同上 |
| R050 | 同上 |

## 規格に書かれていないところ・食い違うところ

| 場面 | 決めたこと | 理由 |
|---|---|---|
| JOB の入力が空 | `JOB=?` を書く | 7.5.4 は、ファイルの中身をデータパケットの決まりで書き、ジョブのデータなら 2 行目を JOB にするとしている。表 A.2 の JOB は、ジョブを示せないアップロードの装置に不明値 `?` を送らせている(R225)。ファイルはアップロードではないが、7.5.4 がデータパケットの決まりに従うとしているので、同じ決まりを当てはめた |
| 文字 127(DEL) | JOB に使える | 5.1.8.1 は 32-127 の文字を認め、3.2.12 は制御文字を「32 未満の文字」と定めている。127 はどちらからも除かれない |
| JOB の `"` | 使える | 予約文字(表 1)ではない。ただし 6.2.2 の引用符の決まりで、相手が引用符を外して読むことがある |
| ファイルの中の DRILLE | 基準 C(箱中心)で書く | 規格の本文が食い違っている。5.5.1.5 の始めは、穴あけの基準を「初期化で、または要求ごとに」取り決めるとし、5.5.3 も、初期化をしないときは要求のパケットに DRLFMT を入れるとしている。一方、5.5.1.5 の終わりは、初期化が無ければ DRILLE は使えないとしている。ファイル(7.5)には初期化も要求も無く、7.5 にも DRILLE の扱いは書かれていない。7.5.5 が縁なしフレームの穴あけのファイル(REQ=FRM)を挙げていることから、ファイルで穴を渡すことは想定されているとみなした。そのうえで、取り決めが無くても誤解の少ない箱中心の基準で書く。読む機器が DRILLE と基準 C に対応しているかは利用者が確かめる |
| 半径の単位 | 1/100 mm | 5.4.2 は「1/100 度」と書いているが、形式 4 の説明(5.4.15.4)は半径を 0.01 mm の単位とし、同じ節の例も 25.40 mm などの半径を使っているので、5.4.2 は書き誤りとみなした |
| 箱の中心 | 書いた点の箱の中心 | 形の箱の中心から半径を測ると、点と点の間にある角は測られないので、書いた点の箱の中心は原点から外れる(角のとがった形を 360 点で書くと 0.05 mm ほど)。受け取る側は書いた点から箱を求めるので、書いた点の箱の中心が原点になるまで合わせ直す |
| 箱の中心の許容差 | 0.01 mm | 規格(5.4.8)は許容差を定めていない。R の値の 1 単位が 0.01 mm(5.4.15.4)なので、書いた半径で表せる細かさを許容差にした |
| R の行の長さ | 15 個ずつ。80 文字を超える行だけ分ける | 規格(5.4.15.1)が決めているのは 80 文字の上限だけで、1 行の個数は決めていない。これまでの出力と同じ 15 個ずつにし、上限を超える場合だけ分ける |
