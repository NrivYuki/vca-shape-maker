# テスト項目

このツールで確かめている項目の一覧です。計算は `tests/shape.test.js`、画面は `tests/ui/` で自動で確かめます。自動にできないものは「手で確かめる項目」に残します。書き出す VCA が規格(DCS v3.14)の決まりを守るかのテスト(`tests/conformance.test.js`)は、決まりごとに [conformance.md](conformance.md) にまとめています。

## 動かし方

```
npm test
node tools/trace.js --check
npm run mutate
```

- `npm test` は計算のテストと規格のテストを動かします。`tools/trace.js --check` は、[conformance.md](conformance.md) の「テスト」の決まりにテストがあるか、[conformance-tests.md](conformance-tests.md) が古くないかを確かめます(作り直すときは `npm run trace`)。`npm run mutate` は、`tools/mutate.js` の一覧のとおりに実装をわざと壊し、そのたびにテストが失敗するか(壊れたことを見つけるか)を確かめます。

```
node tests/ui/cdp.js index.html tests/ui/steps.js
```

- リポジトリのフォルダで実行します。3 つ目に画像を置くフォルダを指定できます(省くと OS の一時フォルダの `vca-ui-check`)。
- 画面の検査は、Chrome をヘッドレスで起動して操作します(Node.js 22 以上。`fetch` と `WebSocket` を使う)。Chrome は決まった場所から探し、見つからないときは環境変数 `CHROME` で場所を指定します。
- 各項目の結果が `OK` / `NG` で出て、最後にコンソールのエラー・例外があれば `PROBLEMS` に並びます。画面の画像は指定したフォルダに保存されます。

## 1. 計算(`tests/shape.test.js`、16 件)

| 項目 | 確かめること |
|---|---|
| spline | 制御点を通る |
| superellipse | 指数 2 は楕円で、箱にぴったり収まる。画面の右上は y が小さい側 |
| polarRadii・offset | 半径 10 の円は 10、0.5 広げると 10.5 |
| resampleArc | 周長に沿って等間隔 |
| mirrorRadii | 左右反転は 180° - a |
| toVCA | 玉形幅が A 寸になる。R・L が 360 点・1440 点ずつで、L は R の左右反転。形が無いとき・A 寸が小さすぎるときはエラー |
| toVCA の寸法 | 書いた HBOX・VBOX・CIRC が、R レコードの半径(1/100 mm に丸めた値)から計算した値と 0.005 mm 以内で一致する(360 点・1440 点、右眼・左眼)。返り値の radii と R レコードの値が同じ |
| R の行 | 15 個ずつ並ぶ。半径が 100 mm 以上で値が 5 けたになると、80 文字を超える行だけを分ける(値の合計は変わらない) |
| extract | リムの内側の輪郭を取り出せる(映り込みがあっても穴を埋める)。リムが切れていると「閉じていない」 |
| 穴(DRILLE) | 穴が無いときは FCRV と TRCFMT のあいだに DRILLE=0 を 1 行書き、vca-guide の drillFeatures で「穴なし」と読める。丸穴と長穴を基準 C で書き、drillFeatures で読み直すと、写した眼は入力どおり、反対の眼は x(長穴は終点の x も)の符号が反対で、y・径は同じ(右眼・左眼)。右眼を先に書く。書いた行が vca-guide の drillRecords の出力と同じ。vca-guide が隣に無いときはこの 2 件を飛ばす |
| 穴の内外・座標 | 中心(長穴は終点も)が玉形の外なら inside が false。画像の箱の中心が mm でほぼ (0, 0)、画像の右上が +x・+y。toMM と toPx で行き来できる |

## 2. 画面(`tests/ui/steps.js`)

| 区分 | 確かめること |
|---|---|
| 上の帯 | 「眼 / A / DBL / フレームカーブ / 点の数 / JOB」が出る。寸法のタブで変えると変わる |
| 下の帯 | 形が無いときは「形を作ると…」、形があって入力が誤っているときは「入力を直すと…」と案内。形ができると玉形の幅×高さ・有効径・周長が出る。形を消すと案内に戻る |
| 保存・コピー | 形が無いときは押せない。形ができると押せ、押すと「保存しました」「コピーしました」と出る |
| タブ | はじめは「画像」だけ見える。5 つのタブを押すとその面だけ見える。左右の矢印キーで切り替わり、端から反対の端へ回る。Tab キーで止まるのは選んだタブだけで、各タブが中身の面と結び付いている(aria-controls・aria-labelledby) |
| 隠れたタブの中身 | VCA のタブを開くと、左右の玉形の図が描ける(隠れている間に描けなかった図を描き直す)。VCA のテキストが 360 点 |
| 寸法 | 点の数 1440・左眼・A 50・DBL 20 にすると、上の帯・VCA のテキスト・下の帯が変わる |
| 入力の誤り | 玉形幅 10 mm は誤りと知らせ、別のタブを開いていても見える。直すと消える。JOB が 13 文字なら誤りと知らせて保存できず、`;` があっても誤り。JOB を空にすると誤りではなく、VCA に `JOB=?`、上の帯に「JOB ?」と出る |
| 画像の読み込み | 画像のファイルを読み込み欄に置く(OS からのドラッグ)と読み込み、名前と画素数が出る。画像でないファイルを置くと「画像ファイルを選んでください」と断り、前の画像のまま。画像を貼り付ける(Ctrl+V)と読み込む。「白紙にする」で画像を外し、箱を描く状態になる。「箱を描いて作る」をもう一度押すとやめる |
| 形を作る | 白紙に箱を描くと形ができる。サンプル画像を読み込むと「クリックで自動抽出」になり、レンズの内側をクリックすると形を取り出せる |
| 元に戻す | 形を消す・元に戻す・やり直すが効く |
| 穴 | 穴が無いとき VCA に DRILLE=0 と書き、説明にも出る。「穴を足す」で右眼の鼻側(+x、縁から 3 mm)に径 1.4 mm の穴ができ、左眼には x を反転して書く。数値で位置と径を直せる。終点を入れると長穴になり、反対の眼は終点の x も反転。終点が片方だけなら誤りと知らせ、両方空に戻すと丸穴に戻って知らせが消える。「画像の上で置く」で箱の中心をクリックすると (0, 0) 付近に、前の穴と同じ径で置ける。穴をドラッグすると x が増えて数値の欄も変わり、形は動かない。中心が玉形の外なら知らせ、一覧にも「玉形の外」と出て、内側に直すと消える。写した眼を左眼にすると、左眼が入力のまま、右眼が反転(右眼を先に書く)。下の帯に穴の数。削除すると番号が詰まり、すべて削除すると DRILLE=0 に戻る |
| ダークモード | 画面全体が暗い色になる(画像で確かめる) |
| 画面の幅 | 375・768・1024・1280 px で横にはみ出さない。全体表示のままなら、幅を変えても画像が枠に収まる。拡大中に幅を変えても、中心と倍率を保つ。狭い画面では下の帯のボタンが横幅いっぱいに並ぶ |
| コンソール | 一連の操作でエラー・例外が出ない |

## 3. 手で確かめる項目

- 実際の商品写真での自動抽出(映り込み・影・縁なしフレーム)
- ファイルの選択ダイアログで画像を選ぶ読み込み(OS のダイアログは自動の操作で開けない)
- 点のドラッグ・ダブルクリックでの追加と削除・箱の四隅と辺での伸び縮み(Shift で縦横比を保つ)
- ホイールでの拡大・右ドラッグでの移動
- 保存した VCA を VCA Lens Simulator の画面で見て、形と向きが合って見えるか(値が合うかは、vca-lens-simulator の `tests/flow.test.js` と `tests/ui/flow.js` が、この画面で作った VCA を vca-ptn-converter を通して読み込んで確かめる)
- 穴のドラッグ・画像の上で置く操作を、実際のマウスで(拡大した状態も含めて)

## 4. 仕様として残しているもの

- 「クリックで自動抽出」「箱を描いて作る」のボタンは、押すたびに入る・切れるが切り替わる。サンプル画像を読み込むと自動で「クリックで自動抽出」に入る。
